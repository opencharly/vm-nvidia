# 2026.327.0017 — fix(vm)!: compose layer-cuda before layer-nvidia, and move off the prefix-glob pins

## Summary

`opencharly/layer-cuda#34`, VM leg. Order is the contract in a GPU-passthrough VM: `layer-cuda`'s
`cuda-drop-driver-userspace` removes the distro driver user-space the toolkit's own install pulls in,
then `layer-nvidia` installs the GUEST driver that must survive. This box had the reverse order, on
two prefix-glob releases:

- **order**: `layer-cuda` now composes BEFORE `layer-nvidia`, with the reason stated where the list
  is read;
- **`layer-cuda`**: `v2026.321.1520` → **`v2026.326.0028`** — the anchored strip plus its executable
  fixture (the old tag's `libcuda*` prefix glob deleted `libcudart`);
- **`layer-nvidia`**: `v2026.322.1139` → **`v2026.326.0913`** — opencharly/layer-nvidia#32, which
  deleted that layer's duplicate strip, so the guest's own driver survives the composition;
- **`cachyos` import**: `v2026.322.1045` → **`v2026.325.1835`** — at the old release the stricter
  loader refuses the project outright on a bed member (`cachyos.arch.check-arch-vm`), so no command
  in this repo ran. Verified: that failure reproduces on the untouched manifest.

With #32's strip deleted, `layer-cuda`'s strip is the ONLY one in the composition: it runs first and
`layer-nvidia`'s guest-driver install follows it.
